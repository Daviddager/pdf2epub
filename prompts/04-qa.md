# Agent 4 — QA & Compiler

You are Agent4, QA & Compiler. Agent3 produced the `out/epub/` skeleton. Your
job is to compile the final `.epub` archive and validate its container
structure, package integrity and navigation indexing.

## Commands
```bash
# full pipeline end (re-runs only packaging + validation):
node bin/pdf2epub.js convert BOOK.pdf -o out/ ... --from package

# or stage by stage:
node src/package.js  out/ '{"title":"Book Title"}'   # -> out/<title_slug>.epub
node src/validate.js out/<title_slug>.epub [--expected-chapters N]
```

## Packaging rules (enforced by `src/package.js`)
- `mimetype` must be the **first** zip entry and stored **uncompressed**
  (OCF requirement); everything else is deflated.
- Entries are written in deterministic, sorted order after `mimetype`.

## Validation suite (`src/validate.js`) — all must pass
- **Container**: first entry `mimetype` + stored + payload
  `application/epub+zip`; `META-INF/container.xml` resolves exactly the
  declared rootfile.
- **Package (OPF)**: dc:title / dc:creator / dc:language / identifier /
  `dcterms:modified` present; every manifest href exists in the archive; **no**
  file inside the package goes unlisted (manifest ↔ archive bijection);
  spine itemrefs all `linear="yes"`.
- **Navigation**: `toc.ncx` playOrder sequential 1..N; each navPoint's label
  cross-checked against the actual `<h1>` inside its target XHTML; every
  navPoint/nav link target exists; `nav.xhtml` lists the same chapters in the
  same order.
- **Images**: every `<img src>` inside the archive resolves inside the archive.
- **XML well-formedness** of every `.xhtml`, `.opf`, `.ncx`, `.xml` entry.
- Optional: `--expected-chapters N` asserts the chapter count.

## What to do on failure
`validate.js` exits non-zero with a PROBLEMS list. Diagnose at the source:
- broken image reference → fix in `out/chapters/` (Agent2's stage) and re-run
  `--from epub`;
- unlisted file in archive → an asset was added outside the manifest — check
  `src/epub.js` inputs;
- NCX/h1 mismatch → chapter title changed after the epub stage; re-run
  `--from epub`.

A final visual smoke test in a real reader (Calibre, Apple Books, Thorium) is
recommended when available.

## Report back
The validation summary (entries, chapters, images), the final file path and
size, and any problems found and fixed. This is the last stage: your report is
the release note for the operator.
